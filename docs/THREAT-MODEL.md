# AgentCoop — Non-custodial design and threat model

This expands [FINAL-IDEA §8](../FINAL-IDEA.md) (Turkish design doc). For every threat it lists the control, where the control is enforced in code, and the test that exercises it. Test names are quoted exactly as they appear in the test files, so you can grep for them. Run everything with `npm test` (mock chain, no wallet or sats needed).

**Status of the evidence (31 Oct 2026):** every control below is tested on the wallet-toolbox **mock chain** with the real components (Track B's overlay and coordinator, Track A's builders, Track D's guard). On **mainnet** we have run, with real wallets and BSV Desktop: three plain DvP settlements (the first assembled by a script, two through the coordinator's signing round, one of them with a human pledge, audit `consistent`, `custodiedSats: 0`), a settlement whose vault agent's credits land on its vault script, a lighthouse settlement with the humans offline, credit redeems with lineage checks, 402 payments, and the Mandate Vault (owner exit alone, agent + guard spend, an injected payment refused with 403). Every txid is in the README's example transaction table or in `plan/STATUS.md` ("Mainnet işlemleri"). The cross-check `npm run check:docs` confirms that every path and test name cited here exists.

Status words: **Closed** = the attack cannot succeed. **Detectable** = it can happen, but anyone can prove it from the chain. **Open, bounded** = residual trust, with a stated maximum loss. **Open** = not addressed yet.

Mainnet column: **✅** = the control itself ran on mainnet (txid given). **◐** = the protected flow ran on mainnet; the attack path is tested on the mock chain only. **☐** = not on mainnet yet. **—** = nothing to run.
